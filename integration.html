SERVICE STATUS HUB / PROTOCOL 1.0

多设备接入文档

任何电脑或服务只需定时向统一 HTTPS 接口提交一份 JSON，即会出现在服务心跳台。

接入原则：每台设备使用唯一 service_id；令牌通过环境变量传入，不写进代码仓库、日志或公开文档。

1. 接口信息

上报地址

POST https://liangzai666.com/status-api/v1/status
Authorization: Bearer <STATUS_HUB_TOKEN>
Content-Type: application/json

向状态中心管理员获取写入令牌，并保存为设备环境变量 STATUS_HUB_TOKEN。

2. 数据协议

{
  "service_id": "xianyu-auto-reply.office-pc-01",
  "name": "咸鱼自动回复 · 办公电脑 01",
  "state": "healthy",
  "message": "WebSocket 心跳正常",
  "observed_at": "2026-09-09T08:00:00Z",
  "ttl_seconds": 120,
  "metrics": {"queue": 0},
  "details": {"version": "1.0.0"},
  "source": "device-reporter"
}
字段要求说明
service_id必填建议 <服务>.<设备>，仅小写英文、数字、-_.
state必填healthy / degraded / down / maintenance / unknown
name选填页面展示名称
message选填当前状态摘要
ttl_seconds选填默认 120；超时后页面自动标记为状态过期
metrics/details选填任意 JSON 对象，用于指标与诊断详情

3. Python 最小接入

import json, os, urllib.request

payload = {
    "service_id": "my-service.office-pc-01",
    "name": "我的服务 · 办公电脑 01",
    "state": "healthy",
    "message": "运行正常",
    "ttl_seconds": 120
}
req = urllib.request.Request(
    "https://liangzai666.com/status-api/v1/status",
    data=json.dumps(payload).encode("utf-8"),
    method="POST",
    headers={
        "Authorization": "Bearer " + os.environ["STATUS_HUB_TOKEN"],
        "Content-Type": "application/json"
    }
)
print(urllib.request.urlopen(req, timeout=15).read().decode())

4. PowerShell 最小接入

$headers = @{ Authorization = "Bearer $env:STATUS_HUB_TOKEN" }
$body = @{
  service_id = "my-service.office-pc-01"
  name = "我的服务 · 办公电脑 01"
  state = "healthy"
  message = "运行正常"
  ttl_seconds = 120
} | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri "https://liangzai666.com/status-api/v1/status" `
  -Headers $headers -ContentType "application/json" -Body $body

5. 建议上报逻辑

  1. 每 30–60 秒检测本机服务一次。
  2. 无论健康或故障都上报，状态变化时更新 message。
  3. ttl_seconds 设置为上报间隔的 3–4 倍。
  4. 设备重启后自动启动上报器。
  5. 服务名称相同但设备不同，必须使用不同的 service_id。

7. 24 小时历史

GET https://liangzai666.com/status-api/v1/history?service_id=my-service.office-pc-01&hours=24
GET https://liangzai666.com/status-api/v1/history?hours=24

带 service_id 时返回单个服务；省略时在 services 数组中批量返回全部服务。hours 默认 24，范围 1–168。

{
  "service_id": "my-service.office-pc-01",
  "from": "2026-10-22T10:00:00Z",
  "to": "2026-10-23T10:00:00Z",
  "intervals": [
    {"state": "healthy", "from": "2026-10-22T10:00:00Z", "to": "2026-10-23T10:00:00Z", "seconds": 86400}
  ],
  "uptime_ratio": 1.0
}

时间均为 UTC。历史只保存状态变更点；停止上报后，由服务端按 received_at + ttl_seconds 补写 unknown。历史启用前及首次上报前的空白记为 unknown。Uptime = healthy 秒数 ÷ 整个查询窗口秒数，unknown、down、degraded 和 maintenance 均不计入正常时长。

页面每 30 秒批量读取一次历史，将滚动 24 小时分为 96 格，每格 15 分钟，按 down > unknown > degraded > maintenance > healthy 着色。悬停可查看浏览器所在时区的时间范围和状态。
